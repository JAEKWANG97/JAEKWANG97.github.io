검색을 연결했으니 최신 사실을 안다고 생각하기 쉽다. 하지만 검색 요청이 성공했다는 사실과 필요한 사실을 빠짐없이 확보했다는 사실은 다르다. Exa CTO Jeffrey Pinner의 「What Your AI Doesn't Know」는 이 간극을 다룬다. 발표의 주장과 Exa가 별도로 공개한 평가·검색 문서를 나눠 살펴본다.

## 1. 실제 검색 사례: 미국 기업을 제외하라고 했는데 미국 기업이 나왔다

Pinner는 여러 조건이 담긴 기업 검색을 보여 준다. 키워드가 맞아 보이는 결과라도 미국 밖의 기업을 찾는 요청에 미국 기업을 반환하면 사용할 수 없다. 별도의 문제는 접근 범위다. 검색 시스템이 확보하지 못한 유료·전문 자료는 순위를 잘 매겨도 나오지 않는다. 그는 의미 기반 검색과 정식 제휴 자료의 결합을 구분해 설명한다.

찾은 페이지를 통째로 읽는 비용도 남는다. 리튬이온 전지의 노벨상 수상자를 확인하는 예에서, 긴 페이지보다 질문에 답하는 짧은 출처 발췌를 보여 준다. 발췌는 질문에 맞아야 하며 원문과의 연결이 필요하다.

ATLAS는 조건에 맞는 대상을 찾고 속성을 채우되 행 전체가 맞아야 하는 평가다. **공식 읽기판의 화면 대조 설명**에 따르면 최종 차트 점수는 검색 없음 9%, 키워드 검색 28%, 의미 기반 검색 45%다. 차트의 +56%는 키워드 대비 개선율이지 절대점수가 아니다. 음성 기계 전사의 56이라는 표현과 구분해야 한다. 일반 질문의 정답률이나 다른 데이터에서의 성능 보장도 아니다. [공식 발표·화면 대조 설명](https://ai.engineer/code/2026/talks/jeffrey-pinner)

**해설:** 이 사례들은 하나의 실패가 아니다. 조건을 놓치는 검색, 자료에 접근하지 못하는 검색, 필요한 대목을 비효율적으로 전달하는 검색은 서로 다른 수정이 필요하다. 최종 점수만 보고 어느 한 기능이 모든 개선을 만들었다고 설명해서는 안 된다.

## 2. ATLAS의 설계: 하나를 잘 찾는 것보다 집합을 완성하기

Exa의 별도 기술 보고에서 ATLAS는 547개 과제로 구성된다. 특정 조건을 만족하는 대상들을 발견한 뒤 각 대상에 여러 속성을 붙인다. 대상만 찾았는지, 개별 칸이 맞는지, 행 전체가 맞는지를 나눠 측정한다. 대표 지표인 Row F1은 모든 칸이 맞은 행을 단위로 정밀도와 재현율을 함께 본다.

정답표 작성에도 여러 모델과 검색 제공자를 사용하고, 검색·검증·수정 과정을 거쳤다고 설명한다. 그렇다고 자동 생성된 정답표가 무오류라는 뜻은 아니다. 보고서의 중요한 실험은 검색 결과 상위를 가렸을 때 성능이 얼마나 떨어지는가다. 검색 없이 외워서 푸는 평가라면 검색 품질 차이를 제대로 측정하기 어렵다. 따라서 이 벤치마크는 “최종 점수가 높나”와 함께 “실제로 검색에 의존하나”를 확인하려 한다. 제공자가 직접 만든 평가라는 이해관계는 남는다. [발표 외 자료: ATLAS 기술 보고](https://exa.ai/blog/atlas-benchmark)

> **이 글의 해석:** 특정 인물 한 명의 소속을 맞히는 문제와, 조건을 만족하는 사람을 전부 찾아 각각의 소속까지 맞히는 문제는 다르다. 후자에서는 눈앞에 놓인 답의 오류뿐 아니라 아예 빠진 대상도 세어야 한다. 그 차이를 무시하면 그럴듯한 표가 완전한 조사로 오인된다.

## 3. 발췌의 단위: 페이지마다 같은 양을 읽을 이유가 없다

8월 공개된 Dynamic Highlights 설명은 검색 뒤의 문맥 구성 문제를 다룬다. 페이지마다 독립적으로 발췌하면 같은 사실이 반복되고, 중요한 페이지에서 필요한 부분을 충분히 가져오지 못할 수 있다. 이 방식은 여러 검색 문서를 함께 보고 관련도가 높은 내용에 더 많은 분량을 배정한다.

Exa는 자체 에이전트 실험에서 토큰 사용 감소와 품질 개선을 보고했다. 그러나 짧은 발췌 때문에 답을 놓쳐 재검색 횟수가 늘면 절약분이 사라질 수 있다는 점도 설명한다. 그러므로 한 번의 검색 응답 길이와 작업 전체의 비용은 같은 지표가 아니다. 여기서는 해당 수치를 다른 작업의 보장된 절감률로 옮기지 않는다. [발표 외 자료: Dynamic Highlights](https://exa.ai/blog/dynamic-highlights)

## 4. 원문 발췌, 전문, 생성 요약은 서로 다른 자료다

현재 Contents 문서는 세 가지 출력 형태를 구분한다. 발췌는 페이지의 관련 부분을 가져오고, 전문은 넓은 문맥과 구조를 확인할 때 쓰며, 요약은 언어 모델이 개요나 구조화 필드를 생성한다. 출처에 그대로 있는 문장과 모델이 재구성한 문장을 같은 근거로 취급해서는 안 된다.

문서는 URL별 성공·실패 상태를 확인하도록 하고, 캐시를 이용할지 최신 내용을 가져올지도 제어할 수 있다고 설명한다. 호출 전체가 반환됐다고 모든 URL을 읽은 것은 아니며, 페이지 주소가 현재 존재한다고 내용이 방금 갱신된 것도 아니다. 예외 조항이나 서로 의존하는 절을 판단하는 과제라면 짧은 발췌 대신 더 넓게 읽어야 할 수 있다. [발표 외 자료: Contents API](https://exa.ai/docs/contents/quickstart)

> **이 글의 해석:** 검색형 AI의 결과를 볼 때는 네 층을 나눠야 한다. 대상을 발견했는가, 속성을 검증했는가, 근거 문맥을 충분히 읽었는가, 요구한 시점의 자료인가. 한 층의 성공으로 나머지를 추정하지 않는 것이 이 발표를 실무적으로 읽는 방법이다.

## 범위와 한계

공식 기계 전사와 Exa의 평가 보고·제품 문서를 확인했다. 발표의 비교 수치와 이후 갱신될 수 있는 웹 보고서의 수치를 하나의 동일 실험으로 합치지 않았다. 자료는 제공자의 1차 설명이며 독립 재현은 하지 않았다. 전사 인식 오류가 남아 있고 전체 영상 대조는 하지 않았다. 이 글은 전체 발표의 번역이 아니라 검색의 실패 지점을 분리해 설명한 해설이다.
