코드는 제대로 바뀌었는데 PR 설명은 틀릴 수 있다. 실행하지 않은 검사를 통과했다고 쓰거나, 이전 버전의 결과를 현재 변경의 결과처럼 설명할 수 있기 때문이다. Stephen Chin과 Cassandra Chin의 발표는 구현과 그 구현을 설명하는 기록 사이의 틈을 다룬다.

## 1. 발표: 반복해서 조사하는 작성자 대신 연결된 증거를 준비하다

Cassandra는 학생의 AI 개발 과정을 추적하던 경험을 PR 설명에 적용했다. 결과 코드만으로는 이전 세션의 판단과 실행을 알기 어렵기 때문이다. 초기 방식은 관련 기록을 조사하고 작성·검토·수정을 반복했다. 그러나 기록을 더 넣어도 검사 실행의 순서와 유효성을 잘못 설명하는 문제가 남았다. 작성 모델을 저렴하게 바꾸는 시도는 품질을 떨어뜨렸다고 한다.

대안은 내장형 그래프 계층에서 변경 이유·코드·검사·출처를 연결해 필요한 증거 묶음을 미리 만드는 것이다. 작성자는 이를 바탕으로 설명하고 검토자는 좁은 범위의 불일치를 찾는다. 강한 작성자를 유지하면서 검토를 가볍게 하는 역할 분담이다.

평가는 프로젝트의 PRBench로 수행했다. 실행 기록과 코드를 토대로 모델이 설명 품질을 평가하고 사람이 정확성을 확인했다고 한다. 토큰 감소와 품질 개선은 이 실험의 보고이며 보편적 절감 보장은 아니다. 프로젝트 이름은 자동 전사에서 여러 형태로 인식된다. 공식 프로젝트 사이트를 이번 확인에서 열지 못했으므로 확인되지 않은 철자나 저장소 주소를 확정해 싣지 않았다. 원시 평가 자료를 검토한 것도 아니므로 벤치마크 결과를 독립 검증으로 읽어서는 안 된다.

## 2. 독립적인 배경: 산출물의 출처를 추적한다는 것

소프트웨어 공급망 표준 SLSA는 provenance를 산출물이 어디서, 언제, 어떻게 만들어졌는지 추적할 수 있는 검증 가능한 정보로 설명한다. 빌드 결과를 원본 코드와 연결하는 정보와 소스 변경 과정에 관한 정보를 구분한다. [SLSA 1.2 Provenance](https://slsa.dev/spec/v1.2/provenance)

이것은 발표 시스템이 SLSA를 구현했다는 근거가 아니다. 다루는 목적과 보장 수준도 다르다. 다만 ‘설명이 있다’와 ‘그 설명이 어느 산출물과 과정에 관한 것인지 확인할 수 있다’를 구별하는 배경으로 유용하다.

## 3. 해설: 증거의 양보다 관계가 중요한 이유

여기부터는 필자의 해석이다. 테스트 성공 로그가 있다는 사실만으로 현재 PR을 검증했다고 말할 수는 없다. 그 로그가 어떤 코드 버전에 속하는지 알아야 한다. 같은 명령이라도 실행 위치와 환경이 다르면 의미가 달라질 수 있다.

따라서 좋은 증거 묶음은 짧은 요약만을 뜻하지 않는다. 필요한 관계를 보존한 축약이어야 한다. 어떤 실행이 어떤 변경을 검사했는지, 지금 인용한 결과가 유효한지, 실패를 나중 성공이 실제로 대체했는지 확인할 수 있어야 한다.

반대로 모든 대화를 통째로 전달한다고 이 문제가 자동으로 해결되지는 않는다. 서로 다른 시점의 사실을 섞을 가능성도 커진다. 기록을 줄일 때는 문장의 수보다 무엇을 연결하고 무엇을 생략했는지 설명할 수 있어야 한다.

## 4. 해설: 그래프는 사실을 만들어 주지 않는다

관계를 저장하는 구조를 사용해도 입력 기록이 누락되거나 연결이 틀리면 결과는 틀릴 수 있다. 그래프라는 자료 구조 자체가 진실성을 보장하는 것은 아니다. 수집한 기록의 출처, 연결 규칙, 버전 식별을 검증해야 한다.

검토 모델의 역할을 좁힌다는 것도 중요하다. 증거 묶음과 설명 사이의 불일치를 찾는 일과, 전체 개발 이력을 처음부터 복원하는 일은 난도가 다르다. 더 저렴한 모델을 쓸 수 있는지는 모델의 크기만이 아니라 맡긴 일의 범위에 달려 있다. 그러나 범위를 좁히면서 필요한 반례까지 빼 버렸다면 비용은 줄어도 신뢰도는 떨어질 수 있다.

이 발표를 읽고 PR 작성 과정에 먼저 던질 질문은 ‘더 긴 설명을 받을까’가 아니다. ‘현재 문장의 근거가 현재 코드에 연결돼 있는가’다. 짧아도 그 연결이 분명한 설명이, 길지만 시점이 섞인 설명보다 검토에 도움이 될 수 있다.

## 출처와 한계

공식 웹과 ZIP 전사를 대조했다. 자동 전사의 도구 이름 인식 오류 가능성을 고려해 불필요한 명칭은 피했다. 프로젝트의 비용·품질 결과는 직접 재현하지 않았다. SLSA는 별도 개념 자료이며 준수 주장을 하지 않는다. 3·4절과 그림은 필자의 해설이고 발표자의 발언을 옮긴 내용이 아니다.
