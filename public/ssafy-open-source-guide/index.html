01 · 기여모임 운영 사례

10기 운영 방식

참여자가 이슈를 고르면 운영진이 분석과 해결 방향, PR 제출 전 코드를 검토했습니다. 프로젝트에 코드를 반영할지는 메인테이너가 결정했습니다.

10기의 주요 운영 절차

이슈 선정
문제와 분석을 공유하고, 기존 작업·PR과 수정 범위를 확인했습니다.
구현·검증
수정한 내용을 빌드·테스트하고 어려운 부분은 비동기로 논의했습니다.
제출 전 검토
프로젝트에 PR을 제출하기 전에 운영진의 코드 검토를 받았습니다.
진행 공유
이슈 선정·PR 생성·병합 상태를 공유하고 프로젝트 리뷰에 대응했습니다.

02 · 프로젝트 선정 기준

프로젝트를 고르는 기준

써 본 기술부터 찾아보고, 개발이 꾸준한지와 수정한 내용을 직접 테스트할 수 있는지 확인합니다.

  1. 써 본 기술

    사용한 기능과 의존성에서 출발합니다. 프레임워크뿐 아니라 라이브러리·SDK·빌드·테스트 도구도 살펴봅니다.

  2. 테스트 환경

    고칠 코드의 언어와 테스트, 필요한 장비를 확인합니다. SQL을 써 본 것과 DB 엔진의 C 코드를 고치는 일은 다릅니다.

  3. 개발과 대화

    코드가 꾸준히 바뀌는지, 기여자의 질문과 PR에 답변·리뷰가 달리는지 살펴봅니다.

  4. 기여 규칙

    공식 기여 안내에서 먼저 논의하거나 승인을 받아야 하는지 확인합니다. 댓글과 PR을 읽어 기존 작업자도 확인합니다.

03 · 기여 진행 절차

기여 진행 순서

모임에 참여하지 않아도 기여할 수 있습니다. 진행 방식은 프로젝트의 공식 안내를 따릅니다.

Django는 Trac·GitHub, PostgreSQL은 메일·CommitFest, AndroidX는 주로 AOSP/Gerrit에서 검토합니다.

  1. 문제와 기존 작업 확인

    공식 안내·재현 조건·관련 댓글과 PR을 확인합니다.

  2. 이해와 범위 설명

    참여 허락만 묻기보다, 확인한 문제와 구현·검증 방향을 함께 설명합니다.

  3. 구현·검증

    작게 수정하고 관련 테스트를 실행합니다. 실행하지 못한 검증은 구분해 적습니다.

  4. 변경 제출·검토

    변경 이유와 검증 결과를 제출하고, 리뷰에 따라 수정·재검증합니다.

  5. 결과와 남은 일 정리

    병합·종료·대체 구현·재제출 등 결과와 남은 일을 정리합니다.
